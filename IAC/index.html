1 Apa yang Akan Kita Pelajari?

Hands-on ini mengajarkan cara menggunakan Ansible untuk mengelola infrastruktur berbasis Docker container sebagai pengganti server fisik/VM — ideal untuk belajar IAC di laptop lokal (macOS maupun Windows via WSL2) tanpa biaya cloud.

🎯 Tujuan

  • Memahami konsep IAC secara praktis
  • Menulis Ansible Playbook pertama
  • Mengelola banyak container sekaligus
  • Memahami idempoten
  • Menerapkan Ansible Roles

🛠️ Tools yang Digunakan

  • Docker Desktop (Mac/Windows)
  • Ansible (via pip / brew)
  • Docker SDK for Python
  • Text editor (VS Code)
  • Terminal (zsh / PowerShell+WSL2)

⏱️ Durasi Estimasi

  • Setup Environment: ~20 menit
  • Lab 1: ~20 menit
  • Lab 2: ~25 menit
  • Lab 3: ~30 menit
  • Total: ~95 menit

1 Ansible vs Docker vs Kubernetes — Apa Bedanya?

Pertanyaan ini sangat umum muncul. Ketiganya berkaitan dengan otomasi infrastruktur tetapi memiliki peran, lapisan, dan masalah yang diselesaikan berbeda.

Aspek ⚙️ Ansible 🐳 Docker (Compose) ☸️ Kubernetes
Kategori Configuration Management / IAC Container Runtime / Build Container Orchestration
Pertanyaan yang dijawab "Bagaimana cara mengkonfigurasi server ini?" "Bagaimana cara menjalankan aplikasi ini?" "Bagaimana cara mengelola ratusan container di banyak server?"
Scope OS, packages, files, services, users Container image, jaringan container lokal Cluster container di banyak node
Agentless? ✅ Ya (SSH) — ❌ Butuh kubelet agent di tiap node
Bahasa Konfigurasi YAML (Playbook) YAML (docker-compose.yml) / Dockerfile YAML (manifests)
Self-healing ❌ Perlu dijalankan ulang Terbatas (restart policy) ✅ Ya (ReplicaSet, probes)
Skala Ratusan server 1 host (atau beberapa dengan Swarm) Ribuan container di banyak node
Kompleksitas 🟢 Rendah – Menengah 🟢 Rendah 🔴 Tinggi
Digunakan untuk Provisioning OS, deploy app, patch, hardening security Lokal dev, CI/CD, microservices sederhana Production-grade container platform
Contoh tools sejenis Puppet, Chef, SaltStack Podman, nerdctl OpenShift, Nomad, Docker Swarm
🔑
Kunci memahami perbedaannya: Docker menjawab "apa yang dijalankan", Ansible menjawab "bagaimana lingkungan disiapkan", dan Kubernetes menjawab "bagaimana memastikan aplikasi selalu berjalan dan bisa di-scale". Ketiganya saling melengkapi — bukan pengganti satu sama lain!
2 Lapisan Otomasi Infrastruktur

Layer 1: Provisioning (Terraform / CloudFormation)

  • Membuat VM, VPC, subnet, storage di cloud
  • "Infrastruktur kosong" siap pakai
  • Terraform apply → EC2 instance terbuat

Layer 2: Configuration Management (Ansible)

  • Install OS packages, copy files, setup services
  • Konfigurasi VM yang sudah ada
  • ansible-playbook → nginx terinstall & berjalan

Layer 3: Container Runtime (Docker)

  • Menjalankan aplikasi dalam container terisolasi
  • Image-based deployment
  • docker run → aplikasi berjalan

Layer 4: Orchestration (Kubernetes)

  • Mengelola ribuan container lintas node
  • Auto-scaling, self-healing, load balancing
  • kubectl apply → deployment production-ready
✅
Apakah mungkin menggabungkan semua ini? YA! Stack umum di industri: Terraform (buat infra cloud) → Ansible (install Docker & konfigurasi node) → Docker (build image) → Kubernetes (deploy di production).
3 Ansible + Docker: Kombinasi Sempurna untuk Belajar

✅ Keunggulan Setup Ini

  • Tidak butuh VM berat atau cloud berbayar
  • Container startup < 1 detik
  • Bisa simulate multi-server di 1 laptop
  • Reset lingkungan instan (docker rm)
  • Sama persis dengan server Ubuntu sungguhan
  • Berjalan di macOS dan Windows (WSL2)

⚠️ Keterbatasan (vs Server Sungguhan)

  • Tidak bisa test full kernel modules
  • systemd perlu konfigurasi khusus di container
  • Tidak ada isolasi network yang kompleks
  • Tidak ideal untuk test firewall rules (iptables)
⚠️
Catatan: Di hands-on ini, kita menggunakan Docker connection plugin Ansible (bukan SSH biasa). Ansible berkomunikasi langsung ke container via Docker socket, sehingga tidak perlu setup SSH key di dalam container.

Lab 1 First Playbook — Install Nginx di Container

🎯 Tujuan

Jalankan playbook Ansible pertama untuk install nginx di dalam container Docker

⏱️ Durasi

~20 menit

📁 Folder

~/ansible-docker-lab/lab1/
1
Siapkan Container Target

Kita buat container Ubuntu yang akan menjadi "managed node" Ansible:

shell
# Pull image Ubuntu 22.04
docker pull ubuntu:22.04

# Jalankan container (tetap hidup di background)
docker run -d \
  --name web-target \
  --hostname web-target \
  -p 8080:80 \
  ubuntu:22.04 \
  sleep infinity

# Cek container berjalan
docker ps
💡
sleep infinity membuat container tetap hidup tanpa menjalankan service apapun. Ansible akan SSH masuk (via Docker connection plugin) untuk menginstall nginx.
2
Buat Inventory File

File inventory mendaftarkan host yang akan dikelola Ansible. Kita gunakan Docker connection plugin agar Ansible berkomunikasi langsung ke container:

yaml · lab1/inventory.yml
---
all:
  children:
    webservers:
      hosts:
        web-target:
          ansible_connection: community.docker.docker
          # Nama container Docker sebagai host
          # Tidak butuh SSH key!
3
Buat Playbook

Playbook adalah "resep" instruksi Ansible. Setiap task mendefinisikan satu aksi yang bersifat idempoten:

yaml · lab1/playbook.yml
---
- name: Setup Web Server di Container
  hosts: webservers
  gather_facts: yes

  tasks:

    - name: Update apt cache
      ansible.builtin.apt:
        update_cache: yes
        cache_valid_time: 3600

    - name: Install nginx
      ansible.builtin.apt:
        name: nginx
        state: present

    - name: Buat halaman HTML custom
      ansible.builtin.copy:
        content: |
          <!DOCTYPE html>
          <html>
            <head><title>IAC Hands-On Lab 1</title></head>
            <body style="background:#0a0f1e; color:#4fc3f7; font-family:monospace;">
              <h1>🚀 Ansible berhasil mengkonfigurasi server ini!</h1>
              <p>Container: {{ inventory_hostname }}</p>
              <p>OS: {{ ansible_distribution }} {{ ansible_distribution_version }}</p>
            </body>
          </html>
        dest: /var/www/html/index.html
        mode: '0644'

    - name: Jalankan nginx
      ansible.builtin.shell:
        cmd: nginx -g 'daemon off;' &
      args:
        executable: /bin/bash
      async: 10
      poll: 0
      changed_when: false

    - name: Tunggu nginx siap menerima koneksi
      ansible.builtin.wait_for:
        host: localhost
        port: 80
        timeout: 15

    - name: Verifikasi nginx berjalan
      ansible.builtin.shell: curl -s http://localhost | head -5
      register: curl_result
      changed_when: false

    - name: Tampilkan hasil verifikasi
      ansible.builtin.debug:
        var: curl_result.stdout_lines
4
Jalankan Playbook
shell
# Masuk ke folder lab1
cd ~/ansible-docker-lab/lab1

# Aktifkan virtual environment (jika belum)
source ../.venv/bin/activate

# Tes koneksi ke container dulu

# Jalankan playbook!
ansible-playbook -i inventory.yml playbook.yml

TASK [Install nginx] *********************************************
changed: [web-target]

TASK [Buat halaman HTML custom] **********************************

...

✅
Buka browser ke http://localhost:8080 — halaman nginx custom seharusnya muncul!
5
Uji Idempoten — Jalankan Ulang

Salah satu prinsip utama IAC adalah idempoten. Jalankan playbook sekali lagi:

shell
ansible-playbook -i inventory.yml playbook.yml

Perhatikan di PLAY RECAP:

output
PLAY RECAP *******************************************************

✅
changed=0 — Ansible mendeteksi bahwa nginx sudah terinstall dan konfigurasi sudah sesuai. Tidak ada perubahan dilakukan! Ini adalah idempoten.

Lab 2 Multi-Container — Provisioning Beberapa Server Sekaligus

🎯 Tujuan

Kelola 3 container sekaligus dengan group berbeda (webservers & db)

⏱️ Durasi

~25 menit

📁 Folder

~/ansible-docker-lab/lab2/
1
Buat Container dengan Playbook (Menggunakan Modul Docker)

Di lab ini, Ansible sendiri yang akan membuat container Docker (bukan kita yang buat manual). Inilah kekuatan IAC — bahkan pembuatan infrastruktur pun diotomasi!

yaml · lab2/playbook.yml
---
# ─── PLAY 1: Buat container via Ansible ───────────────────────
- name: Provision Container Infrastructure
  hosts: localhost
  connection: local
  gather_facts: no

  vars:
    lab_network: lab2-network
    containers:
      - name: web-1
        ports: "8081:80"
      - name: web-2
        ports: "8082:80"
      - name: db-1
        ports: "3306:3306"

  tasks:

    - name: Buat Docker network
      community.docker.docker_network:
        name: "{{ lab_network }}"
        state: present

    - name: Buat semua container Ubuntu
      community.docker.docker_container:
        name: "{{ item.name }}"
        image: ubuntu:22.04
        state: started
        command: sleep infinity
        networks:
          - name: "{{ lab_network }}"
        published_ports:
          - "{{ item.ports }}"
      loop: "{{ containers }}"

# ─── PLAY 2: Konfigurasi web servers ──────────────────────────
- name: Configure Web Servers
  hosts: webservers
  gather_facts: yes

  tasks:

    - name: Install nginx
      ansible.builtin.apt:
        name: nginx
        state: present
        update_cache: yes

    - name: Deploy halaman HTML (berbeda tiap server)
      ansible.builtin.copy:
        content: |
          <!DOCTYPE html>
          <html><head><title>{{ inventory_hostname }}</title></head>
          <body style="background:#0a0f1e; color:#69f0ae; font-family:monospace; padding:2rem;">
          <h1>Server: {{ inventory_hostname }}</h1>
          <p>Dikonfigurasi oleh Ansible IAC</p>
          <p>IP: {{ ansible_default_ipv4.address }}</p>
          </body></html>
        dest: /var/www/html/index.html

    - name: Jalankan nginx
      ansible.builtin.shell: service nginx start || true
      changed_when: false

# ─── PLAY 3: Konfigurasi database server ──────────────────────
- name: Configure Database Server
  hosts: databases
  gather_facts: yes

  tasks:

    - name: Install MySQL client tools
      ansible.builtin.apt:
        name:
          - mysql-server
          - mysql-client
        state: present
        update_cache: yes

    - name: Buat file konfigurasi MySQL
      ansible.builtin.copy:
        content: |
          [mysqld]
          bind-address = 0.0.0.0
          max_connections = 150
        dest: /etc/mysql/mysql.conf.d/lab.cnf

    - name: Catat info server di file
      ansible.builtin.copy:
        content: "DB Server: {{ inventory_hostname }}, OS: {{ ansible_distribution }}"
        dest: /tmp/server-info.txt

Lab 3 Ansible Roles — Kode IAC yang Terstruktur & Reusable

🎯 Tujuan

Refactor Lab 2 menggunakan Ansible Roles agar kode lebih modular dan reusable

⏱️ Durasi

~30 menit

🧩 Konsep Baru

Roles, Handlers, Jinja2 Templates, Tags
💡
Mengapa Roles? Ketika playbook makin kompleks, kode menjadi panjang dan sulit di-maintain. Roles memecah playbook menjadi komponen-komponen terpisah yang bisa digunakan ulang di project berbeda — seperti fungsi/module di programming biasa.
1
Buat Role: webserver
yaml · lab3/roles/webserver/tasks/main.yml
---
# Tasks utama role webserver

- name: Install paket yang dibutuhkan
  ansible.builtin.apt:
    name:
      - nginx
      - curl
    state: present
    update_cache: yes
  tags: install

- name: Deploy halaman utama dari template
  ansible.builtin.template:
    src: index.html.j2
    dest: /var/www/html/index.html
    mode: '0644'
  notify: restart nginx
  tags: configure

- name: Pastikan nginx berjalan
  ansible.builtin.shell: service nginx start || true
  changed_when: false
  tags: service

- name: Verifikasi HTTP response
  ansible.builtin.uri:
    url: http://localhost
    status_code: 200
    timeout: 10
  register: http_result
  tags: verify

- name: Tampilkan status HTTP
  ansible.builtin.debug:
    msg: "✅ HTTP {{ http_result.status }} - {{ inventory_hostname }} OK"
  tags: verify
2
Buat Handler

Handler adalah task yang hanya dijalankan ketika ada perubahan yang men-trigger notify:

yaml · lab3/roles/webserver/handlers/main.yml
---
- name: restart nginx
  ansible.builtin.shell: service nginx restart || true
  changed_when: false
💡
Handler restart nginx hanya berjalan jika task "Deploy halaman utama dari template" melakukan perubahan. Jika HTML tidak berubah, nginx tidak akan di-restart. Ini mencegah downtime yang tidak perlu!
3

Buat Site Playbook & Inventory

# ─── PLAY 1: Buat container ───────────────────────────────────
- name: Provision Lab Infrastructure
  hosts: localhost
  connection: local
  gather_facts: no

  tasks:
    - name: Buat network lab3
      community.docker.docker_network:
        name: lab3-network
        state: present

    - name: Buat container web servers
      community.docker.docker_container:
        name: "web-{{ item.id }}"
        image: ubuntu:22.04
        state: started
        command: sleep infinity
        networks:
          - name: lab3-network
        published_ports:
          - "808{{ item.id }}:80"
      loop:
        - { id: "1" }
        - { id: "2" }
        - { id: "3" }

# ─── PLAY 2: Terapkan role webserver ──────────────────────────
- name: Configure All Web Servers
  hosts: webservers
  gather_facts: yes

  vars:
    site_title: "Advanced Services — IAC Lab 3"

  roles:
    - role: webserver
      # Satu baris ini menggantikan semua tasks yang panjang!

Tantangan Lanjutan (Opsional)

🎯 Tantangan 1: Role Variables

Tambahkan file roles/webserver/defaults/main.yml dengan default variable site_title dan admin_email. Override di site.yml.

🎯 Tantangan 2: Kondisional

Tambahkan task yang membuat file /var/www/html/health.txt berisi status server, dan tambahkan task verifikasi menggunakan ansible.builtin.assert.

🎯 Tantangan 3: Cleanup Role

Buat play ke-3 di site.yml yang menghapus semua container menggunakan community.docker.docker_container dengan state: absent. Jalankan dengan --tags teardown.

🎯 Tantangan 4: Ansible Vault

Buat file variabel terenkripsi untuk menyimpan "password" database: ansible-vault create secrets.yml. Gunakan variabel tersebut di playbook.
